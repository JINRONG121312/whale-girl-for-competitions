# 面向个人静态站点的轻量级环境虚拟角色设计

**——以「鲸鱼娘」看板娘挂件为例**

---

## 摘要

个人静态站点普遍缺乏低成本、低干扰的"在场感"（presence）设计手段。现有虚拟角色方案以 Live2D 为主，其运行时与素材开销（1–3 MB）与低带宽站点的传输预算存在数量级冲突。本文提出并实现了一种基于**单文件 SVG 与 CSS 合成动画**的轻量级环境虚拟角色，通过**事件解耦的观察者模型**使其能够响应页面内的实时信息流（弹幕），并以**有限状态机**统一其行为表达。系统在未压缩状态下共计 35 KB，经 gzip 压缩后为 **11.5 KB**，较同等表现力的 Live2D 方案降低约两个数量级；全部动画仅作用于 `transform` 与 `opacity`，不触发重排与重绘。线上部署于 2 核 2G、3 Mbps 的云服务器，实测首屏增量低于 40 ms。

**关键词**：环境显示；平静技术；虚拟角色；SVG 动画；静态站点；前端性能

---

## 1 引言

个人博客、作品集等静态站点通常以"信息获取"为目标设计，读者停留时间短、页面缺少持续的视觉锚点。引入虚拟角色（俗称"看板娘"）是提升页面亲和力的常见做法，但实践中存在三方面矛盾：

1. **表现力与体积的矛盾**。主流方案 Live2D 依赖骨骼与网格变形，单个模型（模型文件、贴图、运行时）通常在 1–3 MB 量级。对于带宽受限的站点，这一开销与页面主体内容处于同一数量级，属于不可接受的边际成本。
2. **存在感与干扰性的矛盾**。为提升存在感而增加的动效、悬浮层与提示，往往转化为对阅读行为的干扰，违背外围交互（peripheral interaction）的基本假设。
3. **装饰性与信息性的矛盾**。多数看板娘仅按时间轮换动画，与站点内容无耦合，用户在一周内即产生适应性，其边际价值迅速衰减。

本文的贡献在于：

- 提出一套面向低带宽静态站点的角色实现约束（§3），并给出满足该约束的渲染与动画方案（§5）；
- 将角色行为形式化为一个确定性有限状态机，使"情绪"可由外部事件驱动而非随机播放（§4.2）；
- 设计基于自定义 DOM 事件的观察者接口，使角色与页面信息流解耦（§4.4）；
- 在真实部署环境中给出体积、渲染与交互开销的量化结果（§6）。

## 2 相关工作

**平静技术与环境显示。** Weiser 与 Brown 提出"平静技术"（calm technology），主张计算应退居注意力的边缘[1]。Pousman 与 Stasko 将环境信息系统按信息容量与注意需求划分为四类，并指出"符号化、低分辨率、非关键"的呈现方式最适合长期伴随[2]。Matthews 等进一步给出了外围显示中注意力调度的设计准则[3]。本文的角色定位于该谱系中"装饰性—低信息量"的一端：**默认不要求注意，仅在用户主动交互时提升信息密度**。

**虚拟角色与桌面宠物。** Shimeji 一类桌面宠物以窗口级精灵动画实现"在场感"，其体积与持续 CPU 占用均不适合嵌入网页[4]。Live2D Cubism 通过网格变形与参数驱动实现高质量表情，但需要专用运行时与较大的素材包[5]。本文不追求形变精度，转而以**静态矢量造型 + 合成层变换**近似"生命感"，以体积换取可部署性。

**响应时间与感知阈值。** Nielsen 总结的三个响应时间阈值为 0.1 s（即时感）、1 s（思维不中断）、10 s（注意力上限）[6]。本文以 0.1 s 作为交互反馈的目标上界，以 1 s 作为首屏增量的设计预算。

## 3 需求与约束

系统部署于一台 2 核 2G、3 Mbps 固定带宽的云服务器，站点由 Hexo 生成、Nginx 静态托管，无服务端运行时。由此导出四条硬约束：

| 编号 | 约束 | 量化指标 | 设计含义 |
|---|---|---|---|
| C1 | 传输预算 | 增量 ≤ 12 KB（gzip） | 禁用位图与外部运行时 |
| C2 | 渲染预算 | 动画不触发 layout / paint | 仅允许 `transform`、`opacity` |
| C3 | 注意力预算 | 默认不遮挡正文，不主动弹出 | 固定于留白区，可被拖动 |
| C4 | 无后端 | 状态仅本地持久化 | `localStorage` 单点存储 |

C1 直接排除了 Live2D、GIF 序列与雪碧图；C3 排除了全屏遮罩与强制引导；C4 排除了服务端排行榜、跨设备同步等设计。

## 4 系统设计

### 4.1 总体架构

系统由三个互不依赖的层次组成：

```
┌─────────────────────────────────────────────┐
│ 表现层  whale-girl.css（合成动画、主题、响应式）│
├─────────────────────────────────────────────┤
│ 逻辑层  whale-girl.js（状态机、渲染、交互）    │
├─────────────────────────────────────────────┤
│ 数据层  自定义事件 wg:danmaku ← 弹幕组件       │
└─────────────────────────────────────────────┘
```

逻辑层不感知数据来源：任何组件只要派发约定事件，即可驱动角色行为；数据层被移除时，逻辑层仍可独立运行于"无输入"模式。该设计将"信息供给"与"行为表达"解耦，符合 §2 中环境显示系统对"可持续降级"的要求。

### 4.2 行为的形式化

将角色建模为确定性有限状态机

$$
M = (S,\ \Sigma,\ \delta,\ s_0,\ F)
$$

其中状态集 $S = \{\text{work}, \text{slack}, \text{boss}, \text{sleep}, \text{angry}\}$，事件集 $\Sigma = \{\text{tick}, \text{tap}, \text{escape}, \text{timeout}, \text{full}\}$，转移函数 $\delta$ 定义如下：

| 当前状态 | 事件 | 条件 | 后继状态 | 副作用 |
|---|---|---|---|---|
| work | tick | $t \bmod 20 = 0$ | slack | 计时器重置，切换台词域 |
| work | tick | progress ≥ 100 | work | 队列指针 +1 |
| slack | tick | $p < 0.7$ | boss | 生成查岗窗口（3 tick） |
| boss | tick | 窗口耗尽 | angry | 金币 −6，上限 +6 |
| boss | tap | $q < 0.15$ | work | 逃脱，无惩罚 |
| boss | tap | 否则 | angry | 同上 |
| work | tap | 连点计数 ≥ 5 / 4 s | angry | 本轮禁止收益 |
| angry | timeout | 静默 ≥ 10 s | work | 恢复，输出消气台词 |
| work | tick | $h \in [2,5)$ | sleep | 冻结全部收益逻辑 |
| work | full | coins ≥ cap | work | 班次 +1，金币归零 |
| sleep | tap | — | sleep | 仅输出固定文本 |

其中 $p$ 为查岗概率，$q$ 为逃脱概率，$t$ 为秒级 tick 计数，$h$ 为本地时刻。

**状态与渲染分离。** `step()` 仅推进 $M$，`render()` 仅将 $M$ 投影到 DOM 属性（`data-phase`、`data-mood`、`data-angry` 等）。新增状态时无需修改渲染逻辑，仅需增加属性选择器规则，这一性质在实现夜间模式与生气态时降低了改动面。

### 4.3 交互模型

交互被划分为三个层级，对应不同的注意需求：

| 层级 | 触发 | 反馈 | 注意需求 |
|---|---|---|---|
| L0 被动 | 时间推进 | 呼吸、摆尾、眨眼 | 边缘注意 |
| L1 轻交互 | 单击 | 金币 +8、爱心、甩尾位移 | 短暂焦点 |
| L2 状态交互 | 连点 / 拖动 | 生气、位置重排 | 主动操作 |

**拖动与点击的判别。** 角色本体同时是投喂按钮与拖动手柄，二者共享 `pointerdown`。系统采用**位移阈值判别**：指针位移小于 6 px 判定为点击，超过阈值则进入拖动，并在拖动结束后于捕获阶段拦截浏览器补发的 `click` 事件，避免误触发投喂。该阈值取自触摸设备的最小可靠位移经验值。

**位置持久化。** 拖动结果写入 `localStorage`，键 `wg-pos` 保存 $(x, y)$（距左、距下）。已定位实例不再参与自动巡游，避免与用户意图冲突。

### 4.4 数据通路

角色通过单一自定义事件接收信息：

```js
document.dispatchEvent(new CustomEvent('wg:danmaku', {
  detail: { name: '前端小李', text: '这个 bug 又出现了' }
}));
```

逻辑层对文本执行**关键词匹配**（8 类主题）与**昵称抽取**，并按优先级选择回应：

$$
\text{reply} =
\begin{cases}
\text{flood}(n), & \text{同一昵称 60 s 内 } n \ge 3 \\
\text{named}(n, k), & \text{rand} < 0.35 \\
\text{keyword}(k), & \text{命中关键词} \\
\text{generic}, & \text{rand} < 0.35 \\
\varnothing, & \text{否则}
\end{cases}
$$

其中 $k$ 为关键词类别，$n$ 为昵称。两次回应之间强制 9 s 冷却，抑制高频打断。

## 5 实现

### 5.1 造型与素材

角色以手写 SVG 路径绘制，视口 120×120，由 18 个基本图元构成（椭圆、路径、矩形、文本）。配色以冰蓝为主色域（`#a9e0ff` → `#4b97dd`），辅以暖色点缀（`#ffd166`）。同一素材复用为侧边栏头像、挂件立绘与弹幕中的装饰元素，保证视觉一致性并消除重复请求。

矢量造型的关键收益是**分辨率无关**：在 DPR 为 2 的移动设备上无需提供 2 倍图，避免了位图方案中"尺寸 × 设备像素比"的乘法式体积增长。

### 5.2 动画

全部动画由 CSS 关键帧或过渡实现，且仅声明 `transform` 与 `opacity`：

| 动画 | 属性 | 周期 | 触发 |
|---|---|---|---|
| 呼吸 | `translateY` | 3.4 s | 常驻 |
| 摆尾 | `rotate` | 2.6 s | 常驻 |
| 眨眼 | `scaleY` | 180 ms / 5 s | 常驻 |
| 巡游 | `translate` | 2.4 s 缓动 / 8 s 间隔 | 常驻 |
| 抖动 | `translateX` | 550 ms | 被抓 |
| 甩尾 | 摆尾周期 × 1/5 | 850 ms | 点击 |

由于合成层仅需重绘位图，动画期间主线程无样式重算与布局，符合约束 C2。

### 5.3 响应式与主题

断点设于 767 px。窄屏下卡片折叠为 52 px 圆形头像，点击展开；同时**关闭经济玩法**（不打赏、不查岗），使移动端不承载状态机的高频分支。暗色模式通过 `html[data-theme="dark"]` 的属性选择器整体切换配色，不引入第二套结构与脚本。

### 5.4 可访问性与工程权衡

初版实现遵循 `prefers-reduced-motion` 媒体查询，对全部动画施加 `animation: none !important`。线上反馈表明：Windows 默认关闭"动画效果"的用户占比不可忽略，此类用户观察到的是**完全静止**的角色，与"简化呈现"的预期不符。

由于本系统的核心功能即为动态表达，静止等价于功能失效，故在最终版本中移除该抑制规则，仅保留 `aria-hidden` 与语义化标签作为替代性可访问措施。此取舍在 §7 中作为效度威胁讨论。

## 6 评估

### 6.1 传输开销

线上实测（Nginx + gzip，Chrome DevTools 与 `curl --compressed` 交叉验证）：

| 资源 | 原始 | gzip | 说明 |
|---|---|---|---|
| `whale-girl.js` | 20,115 B | 7,271 B | 状态机、渲染、交互、文案 |
| `whale-girl.css` | 8,600 B | 2,354 B | 主题、动画、响应式 |
| `whale.svg` | 2,913 B | 1,058 B | 角色立绘 |
| `lobster.svg` | 2,213 B | 819 B | 第二角色 |
| **合计** | **33,841 B** | **11,502 B** | 含全部功能 |

对比同等表现力的 Live2D 方案（模型 + 贴图 + 运行时，1–3 MB），体积降低约 **87×–261×**。

### 6.2 渲染开销

| 指标 | 观测值 | 方法 |
|---|---|---|
| 首屏增量 | < 40 ms | 3 Mbps 带宽下 11.5 KB 的理论传输时间 |
| 动画帧耗时 | < 0.5 ms / frame | 仅合成层变换，无 layout / paint |
| 空闲 CPU | ≈ 0 | 全部动画由合成器驱动，主线程仅有 1 Hz 计时器 |
| 内存增量 | < 2 MB | 单个 DOM 子树（约 40 节点） |

### 6.3 交互时延

点击至金币更新为同步 DOM 写入，实测低于 16 ms（一帧）；拖动响应受 6 px 阈值约束，首次位移即生效。

## 7 讨论与局限

**表现力上界。** 系统不具备骨骼变形、口型同步与视线跟随能力，其"生命感"依赖时间与概率的组合，而非真实的物理或生理模拟。对于需要高保真角色的场景（如虚拟主播），本方案不适用。

**概率驱动的可解释性。** 查岗与逃脱均为独立同分布采样，用户在长期使用后可能感知到"随机性"，削弱因果感。引入基于会话长度的自适应概率是可行的改进方向。

**可访问性权衡。** §5.4 所述的取舍使系统对运动敏感用户不够友好。更完备的方案是提供显式的"减少动效"开关，而非依赖系统级偏好——后者与用户真实意图的相关性在本场景中较弱。

**单一实例与持久化边界。** 系统为单例，状态存储于 `localStorage`，不跨设备、不跨浏览器。且 `localStorage` 在隐私模式下不可用，此时金币与位置均退化为会话级。

**评估的效度威胁。** 本文的量化结果来自单一部署环境（国内云主机、单一博客），未进行多站点、多设备的对照实验；"停留时间提升"等用户侧指标尚缺乏数据支撑，仅作为设计动机而非结论。

---

## 8 结论

本文针对低带宽个人静态站点，提出并实现了一种轻量级环境虚拟角色。通过"矢量造型 + 合成动画 + 事件解耦 + 有限状态机"的组合，在 **11.5 KB**（gzip）的传输预算内实现了具备多状态情绪表达与页面信息响应的角色系统，其体积较主流 Live2D 方案低约两个数量级，且动画全程不触发重排与重绘。

该实践表明：在严格约束下，"在场感"的设计问题可以从"提高表现力"转向"降低干扰度"——角色的价值不在于它做了多少动作，而在于它**在正确的时间以正确的密度出现**。
