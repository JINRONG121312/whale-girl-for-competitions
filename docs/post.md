# 我在网页左下角，养了一只鲸鱼娘

> 项目地址：**https://github.com/JINRONG121312/whale-in-my-web**
> 一只 11.5 KB 的看板娘，纯 SVG + CSS，不依赖任何框架。可以先看 [演示](https://github.com/JINRONG121312/whale-in-my-web/blob/main/demo/index.html)，双击就能跑。

---

## 一

事情是从一块 99 块钱一年的服务器开始的。

买完才发现，2 核 2G、3M 带宽、40G 硬盘——这点家当，能干的活不多。跑不了大模型，装不下重型框架，连开个 MySQL 都让内存吃紧。

于是我想：既然什么重活都干不了，那就干点轻的。

比如，在页面左下角养一只小生物。

---

## 二

看板娘这东西，网上方案很成熟。最流行的是 Live2D——能眨眼、能呼吸、能跟着鼠标转头。

我试了一下，一个模型加贴图，起步 1MB 到 3MB。

我的服务器峰值带宽是 **375KB/s**。也就是说，光是把这只小生物加载出来，访客要对着白屏等 3 到 10 秒。

为了一个角落里的装饰，把整站拖慢一个数量级——这不划算。

所以我选了最不酷的方案：**手绘 SVG + CSS 动画**。

一张 3KB 的矢量图，任意分辨率都不糊，一个请求都不多发。代价是它不会跟着鼠标转头，也做不了骨骼动画。

我认了。

后来我一直在想这件事：**做加法谁都会，难的是知道自己不该加什么。** 每一个「再加一点会更酷」的念头，背后都是访客的一次等待。

---

## 三

静态图片看三天就腻。

第一版我给了它两个状态：写代码、摸鱼。每 20 秒摸一次鱼，摸 4 秒。

结果像个电子宠物表——按时间切图片，没有"被影响"的感觉。

于是我开始给它加"动机"。

**第一层，给它利益。** 加了鱼币，打赏一次 +8，攒满一罐换下一班。

**第二层，给它代价。** 摸鱼的时候，会有个龙虾娘老板来查岗，被抓扣 6 个币。

但只扣钱太无趣了。我加了一条：**被抓的时候，攒钱上限也涨 6**。

于是它变成了一个黑色幽默——你越被抓，罐子越大，越能装。惩罚变成了另一种奖励。

**第三层，给它人格。** 连着戳它 5 次，它会生气，生气期间一个币都不给；但你停手 10 秒，它自己就消气了，还要嘴硬一句"算你识相"。

晚上 11 点后，台词换成"眼睛要瞎了""咖啡已经第三杯"；凌晨 2 点到 5 点，它直接打瞌睡，谁都不理，点它只回一句"别吵，睡着了"。

到这一步，它才不像是"随机换台词的程序"，而像**一个有点小脾气的室友**。

---

## 四

我一度把它的卡片做得挺精致：白底、圆角、边框、阴影、右上角一个 ×。

然后我自己打开看了一眼——**像后台管理面板里的一个通知条。**

问题不在细节，在形态。卡片属于"界面"，浮在页面上的才属于"角色"。

改成"贴纸"之后：容器完全透明，没有边框和阴影，只有对话气泡有一层淡淡的底，鲸鱼直接浮在页面上，和背景是同一层。

顺眼多了。

另一件事是**位置**。

一开始它固定在左下角。后来发现，文章长了，它会压在正文上。于是我让它每 8 秒在左下角一小片水域里游一游——不是为了好玩，是为了"存在感"：一个会动的东西，你会下意识避开它，而一个不动的方块，你只会觉得它挡住了字。

再后来，我干脆让它**可以被拖走**。按住就能拖到任何地方，松手记住位置。

用户不舒服的地方，不该由我来猜，应该由他自己摆。

---

## 五

博客上我做了个弹幕功能，读者的留言会从页面顶上飘过去。

某天我想：它能不能"看见"这些弹幕？

技术上不难，只要让弹幕组件广播一个事件，挂件监听着就行：

```js
document.dispatchEvent(new CustomEvent('wg:danmaku', {
  detail: { name: '前端小李', text: '这个 bug 又出现了' }
}));
```

然后它就能接话了。

有人在弹幕里说"这个 bug 又出现了"，它会回一句"这个 bug 我看了三遍，还是不懂"。

有人刷屏，它会说"你先歇会儿"。

再后来，我让它记住弹幕里的昵称——"前端小李"来说话，它会回"前端小李 又来啦"。

**那一刻它才真正活了。** 不是因为它多了几个动画，而是因为它开始"认识人"了。

顺便说，这层耦合是故意做松的：挂件只监听事件，不知道数据从哪来。所以你可以接自己的接口、接 WebSocket、甚至接一份静态 JSON——**换数据源不用改一行挂件代码**。这一条也是我在仓库里唯一强调"架构"的地方。

## 六

两个坑值得记一笔。

**第一个坑：好心办坏事。**

我在样式里加了这段，本意是尊重系统的"减少动态效果"设置：

```css
@media (prefers-reduced-motion: reduce) {
  .wg * { animation: none !important; }
}
```

结果有读者反馈："你的鲸鱼是静止的。"

我才意识到，对很多 Windows 用户来说，"动画效果"这个开关是默认关掉的——而我的看板娘**唯一的功能就是动**。关了动画，它就不是"简化版"，它是"坏掉了"。

后来我把这段删了。可访问性很重要，但对一个纯装饰物来说，"能用"优先级更高。

**第二个坑：缓存骗了我一整天。**

服务器上给静态资源设了 30 天强缓存，改完代码刷新，看到的还是旧版本。

一度以为代码没生效，重写了两遍。

最后发现是浏览器根本不请求新文件——**地址没变，它凭什么重新下载？**

从那以后，所有资源地址后面都带一个 `?v=时间戳`。

这件事教会我：**调试的时候，先怀疑缓存，再怀疑自己。**

## 七

这只鲸鱼娘现在占多大？

| 资源 | gzip 后 |
|---|---|
| 挂件 JS | 7.3 KB |
| 挂件 CSS | 2.4 KB |
| 鲸鱼 SVG | 1.0 KB |
| 龙虾娘 SVG | 0.8 KB |
| **合计** | **约 11.5 KB** |

比一张普通的 JPEG 配图还小。

它做的事情是：写代码、摸鱼、被查岗、扣钱、涨上限、换班、生气、消气、打瞌睡、认名字、回弹幕、被拖走、记住自己在哪里。

**11.5KB，换一个人愿意在页面上多待十秒。** 我觉得这笔交易很划算。

## 八、想自己养一只？

代码全部开源了（**非商业许可**，个人博客随便用）：

**仓库**：https://github.com/JINRONG121312/whale-in-my-web

里面除了能跑的代码，还有两份额外的东西：

- **`docs/report.md`** —— 一份学术体例的技术报告。约束推导、状态机形式化、体积与帧预算的实测数据、以及"效度威胁"（诚实写明哪些结论没有实验支撑）。
- **`demo/index.html`** —— 双击就能跑的演示页，不用起服务器、不用装依赖。

使用只需要两个文件：

```html
<link rel="stylesheet" href="src/whale-girl.css">
<script defer src="src/whale-girl.js"></script>
```

Hexo、Butterfly、Vue、纯 HTML 都行，代码里没有一处绑定框架。

如果它对你有用，**点个 star** 是我能收到的最实在的反馈；如果它在你那儿跑不起来，开个 issue，我大概率当天就回。

## 写在最后

这个项目没用什么高深技术。SVG 是手画的，动画是 CSS 的，状态机就是一堆 `if`。

它真正花时间的地方，全在"要不要"上：

- 要不要上 Live2D？——不要，太重。
- 要不要加音效？——不要，会吓人。
- 要不要每次打开都弹出来打招呼？——不要，烦。
- 要不要让它自己跑满屏幕？——不要，那是骚扰不是陪伴。

**做玩具和做产品的区别可能就在这儿：玩具想尽办法让你看见它，产品知道什么时候该消失。**

我的服务器很小，小到只能装下 11KB 的浪漫。

但好像也够了。
